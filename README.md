# handeck (가칭)

**→ [thgamoo.github.io/handeck](https://thgamoo.github.io/handeck/) 에서 바로 씁니다.**

**보드게임 구성품 에디터.** 브라우저에서 카드·토큰·보드를 만들고, 바로 인쇄용 PDF 로 뽑는다.
디자인은 사람이 읽을 수 있는 **JSON 한 파일**로 저장되어 git 에 올리고 공유할 수 있다.

브라우저에서 URL 하나 열면 끝이다. **설치도 계정도 서버도 없다.**
코드를 쓰지 않고, 배울 문법도 없다.

---

## 왜 만드나

`sub3` 카드 352장을 [nanDECK](https://nandeck.com) 으로 뽑아보고, 이어서
«데이터 + HTML 템플릿 + CLI» 형태의 도구를 직접 만들어봤다. **둘 다 실패했다.**

문법은 달랐지만 상호작용은 똑같았기 때문이다 —
텍스트 파일을 고치고, 빌드를 돌리고, 결과를 확인한다.
카드 한 장의 이미지를 3mm 옮기려고 파일을 열고 숫자를 고치고 다시 빌드한다.

**그게 불편했던 것의 정체였다.** 문법이 아니라 루프다.

| | nanDECK | HTML 템플릿 방식 | handeck |
| --- | --- | --- | --- |
| 카드를 만드는 법 | DSL 스크립트 작성 | HTML/CSS 작성 | **화면에서 끌어다 놓기** |
| 위치를 3mm 옮기려면 | 숫자 고치고 빌드 | 숫자 고치고 빌드 | **끌면 됨** |
| 배울 문법 | 지시문 300여 개 | HTML+CSS+`{{ }}` | **없음** |
| 저장 형식 | `.nde` (독자 포맷) | HTML + CSS 파일들 | **`project.json`** |
| 공유 | 스크립트+데이터+에셋 뭉치 | 저장소 통째로 | **파일 하나 (+ 이미지)** |
| 시작하려면 | 설치 | Node 설치 | **URL 열기** |

## 원칙

**1. 편집기가 제품이다.** 브라우저에서 바로 쓴다. 설치·계정·서버 없음.

**2. 저장 형식이 곧 공개 인터페이스다.**
`project.json` 은 사람이 읽고, diff 로 보고, 손으로 고칠 수 있어야 한다.
포맷이 안정적이면 편집기가 바뀌어도 작업물이 남는다.

**3. 조판은 브라우저에 맡긴다.**
한글 줄바꿈·자간·양끝맞춤은 CSS 가 이미 다 한다.
자체 조판 엔진을 짜는 순간 기존 도구들과 같은 곳에서 무너진다.

**4. 틀과 내용을 분리한다 — 문법 없이.**
카드 한 종류는 «베이스 컴포넌트» 하나고, 실제 카드들은 그 인스턴스다.
레이어는 기본적으로 공통이고, «카드마다 다르게» 를 켠 것만 인스턴스에서 편집된다.
그래서 테두리 색을 바꾸면 100장이 같이 바뀐다.

**5. 인쇄가 쉬워야 한다.**
버튼 하나로 재단선 있는 PDF 가 나온다. 63mm 라고 하면 자로 재서 63mm 다.
양면은 앞뒤가 맞물린다. 이건 협상 대상이 아니다.

## 만드는 것

| | |
| --- | --- |
| 카드 · 토큰 · 타일 | 크기·모양(사각/원형) 지정, 데이터로 여러 장 찍기, 앞뒤 |
| 룰북 | 여러 쪽 문서 — *아직* |
| 보드판 | 대형 인쇄물, A4 여러 장으로 쪼개기 — *아직* |

출력: **PDF**(벡터, 인쇄용) · **PNG**(목업·공유용) · PPTX(*아직*)

---

## 시작하기

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 타입 검사 + 정적 파일 (dist/)
npm run check    # 확인 모음 — 조판·히트 테스트·PNG·묶음·예제 검사
```

실제 프로젝트가 어떻게 생겼는지 보려면 **[`example/`](example/)** 의 `project.json` 을
앱에서 «열기» 로 고르면 된다 (보드게임 하나의 구성품 15덱 438장).

브라우저가 열리면 예제 프로젝트가 이미 들어 있다. 왼쪽에서 카드를 고르고,
가운데 판에서 끌어 옮기고, 오른쪽에서 값을 고친다. 저장은 자동(이 브라우저)이고
`저장` 버튼으로 `project.json` 을 받아 둘 수 있다.

## 지금 되는 것

**카드 만들기**

- 레이어 — 이미지 · 글자 · 도형 · 그늘. 끌어서 옮기고 모서리로 키운다
- **컴포넌트와 인스턴스** — 틀 하나를 고치면 카드 100장이 같이 바뀐다.
  «카드마다 다르게» 를 켠 레이어만 카드별로 값을 갖는다
- 정렬 가이드·스냅(Alt 로 끔), 되돌리기/다시, 방향키 미세 조정
- **투명한 곳을 누르면 뒤 레이어가 잡힌다** (Ctrl+클릭이면 무시하고 맨 위)
- 눈금자(mm) · 화면 실물 크기 보정 — 100% 가 자로 잰 63×88mm 가 된다
- **글꼴 직접 넣기** (ttf·otf·woff·woff2) · **키워드**(칩·진하게·색)
- 이미지는 브라우저 안(IndexedDB)에 내용 해시로 저장 — 같은 그림은 한 번만

**내보내기**

- **인쇄/PDF** — A4 에 격자로 깔고 재단선을 긋는다. 양면(앞뒤 맞물림).
  조각끼리 **맞붙여** 깔아 칼질 한 번에 두 장이 잘린다
- **PNG** — 이 카드 한 장, 또는 덱 전체를 격자로. 96~600dpi

**저장 · 공유**

- **`.handeck` 묶음** — 프로젝트 + 그림 + 글꼴을 **한 파일로**. 건네주면 받는 쪽에서
  그대로 열린다. 속은 그냥 zip 이라 압축 프로그램으로 열어 그림만 꺼내도 된다
- **`project.json`** — 사람이 읽고 git 에 올리는 용도. 가볍지만 그림·글꼴은 안 들어간다
- 열기는 둘 다 받는다 (확장자가 아니라 내용을 보고 가른다)
- 자동 저장(이 브라우저) — 새로고침해도 남는다

## 아직 아닌 것

- **도련** — 자를 때 밀려도 흰 테두리가 안 생기게 하는 여유분. 만들어뒀지만
  카드가 커져 보이는 문제가 있어 **꺼뒀다** (`BLEED_ENABLED`). 다음 판에서 손본다.
  집에서 잘라 쓰는 데는 맞붙이기로 충분하다
- 표로 대량 편집 (스프레드시트 붙여넣기 · CSV)
- 여러 개 선택 · 복사/붙여넣기 · 카드별 뒷면
- 룰북(여러 쪽) · 보드판(타일링) · PPTX
- **실물 인쇄 검증** — PDF 안에서 잰 수치는 맞지만 아직 종이로 안 뽑아봤다

## 만듦새

의존성은 **react · react-dom · zustand** 셋뿐이다. 조판·인쇄·PNG 모두
브라우저에 이미 있는 것으로 한다 (CSS 조판, 인쇄 대화상자, SVG `foreignObject`).

- 화면과 인쇄와 PNG 가 **같은 렌더 코드**(`core/render.tsx`)를 쓴다.
  두 벌이 되는 순간 «화면은 이런데 인쇄는 저렇다» 가 생긴다
- 좌표는 전부 mm. 화면 배율은 마지막에 한 번만 곱한다
- 테스트 틀을 들이지 않았다. `checks/run.tsx` 하나로 조판·판정·PNG 조립·편집 상태를
  확인한다(`npm run check`). 브라우저가 있어야 하는 것(IndexedDB·글꼴 등록·래스터화·
  인쇄 대화상자)은 **사람이 띄워서 봐야 한다** — 거기까지 자동으로 보려면
  브라우저 구동 도구를 들여야 하고, 그건 이 규모에 과하다
- 인쇄 실측은 [`docs/print-findings.md`](docs/print-findings.md) —
  Chromium 이 PDF 페이지 크기를 1/300인치에 스냅한다는 것 같은,
  어떤 구조로 만들든 부딪히는 사실들이다
