# v0.1 관문 스파이크 결과

**결론: 전제가 성립한다. 설계대로 진행 가능.**
단, 페이지 크기를 Chromium 에 맡기면 안 된다. 잘라내기로 확정해야 한다.

실행: `npm i && node spike.mjs && python verify.py`
추가 검증: `node size-probe.mjs`, `node size-law.mjs`, `node scale-probe.mjs`,
`python content-scale.py`, `python accumulation.py`

---

## 1. Chromium 의 PDF 페이지 상자는 믿을 수 없다

63 × 88 mm 를 요청하면 **63.161 × 87.884 mm** 가 나온다.

6가지 방법(`preferCSSPageSize` + `@page` mm/in/px, 명시 `width`/`height` mm/in/px)을
전부 시도했으나 **오차가 동일**하다. 계통 오차다.

`size-law.mjs` 로 13개 크기를 측정한 결과 — 출력은 항상 **1/300 인치 격자**에 스냅된다
(격자 편차 0.00004 pt = 0). 300 DPI 디바이스 픽셀 단위다.
다만 요청값 → 격자점 매핑이 단순 반올림이 아니라 ±2 단위까지 튄다.

| 요청 | 실제 | 오차 |
| ---: | ---: | ---: |
| 10 mm | 9.906 | −0.094 |
| 63 mm | 63.161 | +0.161 |
| 100 mm | 99.822 | −0.178 |
| 297 mm | 297.011 | +0.011 |

**오차는 절대량이다.** 63mm 에서 0.11, 841mm(A1) 에서 0.14 — 크기와 무관하다.

## 2. 해법: 넉넉히 렌더하고 잘라낸다

```
조각보다 큰 페이지에 렌더  →  조각을 좌상단에 앵커  →  embedPage(boundingBox) 로 잘라냄
```

페이지 상자의 오차는 잘라내는 순간 사라진다. 배율을 주지 않으므로 왜곡도 없다.

**측정 결과: 63 mm ~ 841 mm 전 구간에서 오차 0.0000 mm.**
Chromium 이 대형 페이지를 거부하는 한계도 없었다(A1 까지 확인).

> 그래서 `@page` 크기는 «잘리지만 않으면 되는 값» 일 뿐이다.
> 최종 치수는 pdf-lib 의 잘라내기 상자가 정한다. **여기가 유일한 진실 공급원이다.**

## 3. 내용물은 정수 CSS 픽셀로 스냅된다 (±0.13 mm)

컨텐츠 스트림을 풀어보면 정체가 드러난다.

```
.24 0 0 -.24 0 298.08 cm    ← 300dpi → pt
3.125 0 0 3.125 0 0 cm      ← 96dpi CSS px → 300dpi
0 0 238 333 re f            ← 63mm = 238.11px 인데 238 로 스냅됨
```

Blink 가 **칠해지는 박스의 가장자리를 정수 CSS 픽셀(1/96 in)로 스냅**한다.
이론 상한은 반 픽셀 = **0.1323 mm**. 측정값이 전부 그 안에 들어 설명이 완결된다.

| 요청 | 그려진 박스 | 오차 | 상대 오차 |
| ---: | ---: | ---: | ---: |
| 63 mm | 62.971 | −0.029 | 0.046 % |
| 297 mm | 297.127 | +0.127 | 0.043 % |
| 594 mm | 593.990 | −0.010 | 0.002 % |
| 841 mm | 841.110 | +0.110 | 0.013 % |

**절대 오차다. 비례하지 않는다.** 크기가 커질수록 상대 오차는 오히려 줄어든다.

실무 판단:

- 재단 공차가 보통 ±0.5 mm 이므로 카드에서는 묻힌다.
- 보드판(594 mm)에서도 절대 0.13 mm. **비례하지 않는 게 핵심이다.**
- 글자와 SVG 는 이 스냅을 받지 않는다. 칠해지는 박스만 해당.
- 다만 잘라내기 경계에 흰 실선이 생길 수 있으므로
  **배경은 블리드 영역까지 넘겨 그린다.** (인쇄에선 어차피 필요한 조치)

## 4. 격자 배치는 누적되지 않는다

시트 PDF 의 배치 행렬을 직접 읽어 확인했다 (`accumulation.py`).

```
  0  0   10.50000 mm   오차 +0.000000   배율 1.0000, 1.0000
  0  1   73.50000 mm   오차 +0.000000   배율 1.0000, 1.0000
  0  2  136.50000 mm   오차 +0.000000   배율 1.0000, 1.0000
```

- 최대 배치 오차 **0.000000 mm** — 각 조각의 좌표를 `origin + index × pitch` 로
  매번 처음부터 계산하기 때문. «옆에 붙이기» 를 반복하지 않는다.
- 배율이 전부 정확히 1.0 — 조각이 늘어나거나 줄지 않는다.
  **원형 토큰이 타원이 되지 않는다는 뜻이다.**
- 좌우 여백 대칭 10.5 / 10.5 mm.

## 5. 한글 회귀 — 전부 통과

nanDECK 을 깨뜨렸던 문자가 최종 시트 PDF 에서 온전히 살아남는다.
텍스트로 추출된다는 것 자체가 **벡터로 남았다**는 증거다(래스터면 추출 불가).

`급` `렉` `붉` — 탭 구분자에서 쪼개졌던 글자
`마` `독` `조` — 스크립트 리터럴 파서를 깨뜨렸던 글자
`—` em dash — CP949 에 없어 `?` 로 소실됐던 문자
`♥` `♠` `金` `①` `✦` — 글리프

> `✦`(U+2726)는 nanDECK 에서 빈칸으로 나와 빌런 토큰 기호를 ♠ 로 바꿔야 했는데,
> **Chromium 은 폰트 대체로 정상 출력한다.** 그 우회가 필요 없어진다.

줄바꿈도 한글 규칙을 지킨다 — `혈술사·` / `진조가` 로 끊는다.

## 6. 설계에 반영할 것

1. **`@page` 크기를 최종 치수로 쓰지 않는다.** 조각 + 여유로 렌더하고 잘라낸다.
2. **잘라내기 상자가 치수의 단일 진실 공급원.** 치수 테스트도 여기에 건다.
3. **배치 시 배율을 주지 않는다.** `drawPage` 에 width/height 를 넘기면
   스냅 오차가 배율로 번져 왜곡된다. 좌표만 준다.
4. **템플릿 규약에 블리드를 필수화한다.** 배경은 재단선 밖까지 넘겨 그린다.
5. 시스템 Chrome 을 쓸 수 있으면 쓴다 (`channel: 'chrome'`).
   Playwright 번들 Chromium 150MB 다운로드를 아낀다. 없으면 자동 대체.

## 브라우저만으로 뽑기 — 결론 (2026-07-31)

**된다.** 로컬 헬퍼 없이 무서버로 확정.

핵심은 **페이지 상자를 조각 크기로 잡지 않는 것**이다. 위에서 잰 대로
`@page { size: 63mm 88mm }` 는 1/300 인치로 반올림돼 0.18mm 까지 틀어진다.
대신 **페이지를 A4 로 고정**하고 조각을 그 안에 mm 좌표로 깐다.

### 실측 — 실제로 뽑힌 PDF 를 뜯어서 잰 값

포커 카드 63×88, A4 맞붙이기 3×3. PDF 내용 스트림에서 사각형 좌표를 읽고
종이 바탕 사각형으로 눈금을 맞춰 환산했다.

| | 기대 | 실측 | 오차 |
|---|---|---|---|
| 종이 | 210 × 297 | 209.889 × 297.037 | −0.111 / +0.037 |
| 카드 폭 | 63.000 | 62.979 | −0.021 |
| 카드 높이 | 88.000 | 87.853 ~ 88.117 | ±0.13 |
| 첫 칸 위치 | 10.500 | 10.585 | +0.085 |
| 칸 간격 | 63.000 | 62.979 / 62.978 | −0.021 |
| 3칸 전체 폭 | 126.000 | 125.957 | −0.043 |

- 위치 오차 **최대 0.085mm**, 3칸 누적 **0.043mm** — 위에서 잰 «내용은 정수 CSS px 로
  스냅되지만 누적되지 않는다» 와 일치한다
- 카드 **높이만 ±0.13mm 흔들린다.** 정수 px 스냅의 절대 오차 그대로다.
  칼로 자르는 정밀도(0.5mm 안팎)보다 한참 작아 실사용에 지장 없다
- 종이 상자의 −0.111mm 는 Chromium `printToPDF` 고유의 양자화다. **내용 좌표에는
  영향이 없고**, 실제 프린터로 뽑을 때는 프린터가 진짜 용지 크기를 쓰므로 무관하다

### 붙이면서 걸린 것

1. **인쇄 화면을 앱 안에 두면 안 된다.** `@media print` 에서 `.app` 을 숨겼는데
   감싸고 있는 `#root` 가 `100vh` 를 그대로 차지해 첫 장이 한 화면만큼 밀리고
   **빈 쪽이 하나 더** 생겼다. `createPortal` 로 body 밑에 붙이고 `#root` 째 숨겨 해결.
   (증상: 1시트인데 PDF 2쪽, 2시트인데 3쪽)
2. `-webkit-print-color-adjust: exact` 를 안 걸면 사용자가 «배경 그래픽» 을 끈 순간
   카드가 흰 종이가 된다. 전역으로 강제한다.
3. 사용자가 대화상자에서 **여백 없음 / 배율 100%** 를 맞춰야 한다. 안내 문구를
   미리보기 화면에 박아뒀다 — 안 적으면 반드시 틀린다.
