실제로 만들고 있는 보드게임의 구성품을 handeck 프로젝트로 옮긴 것.
**앱에서 «열기» 로 `project.json` 을 고르면 된다.**

```
덱 15개 · 카드 종류 116종 · 총 438장
```

## 다시 만들기

```bash
node example/build.mjs
```

`build.mjs` 안의 배열이 곧 카드 목록이다. 문서가 개정되면 그 배열만 고쳐 다시 돌린다.
**손으로 JSON 을 짜지 않는 이유**는 수량 때문이다 — 능력 카드는 7종인데 100장이고,
그건 `qty` 한 칸으로 접힌다. 표를 그대로 옮기면 끝난다.

`npm run check` 가 이 파일을 검사한다: 앞뒤 규격 일치, 값이 가리키는 레이어 존재,
**문서가 정한 장수와 실제 장수 일치**(능력 100 · 단서 27 · 운명 48 …),
재앙 뒷면이 운명 뒷면과 동일한지까지. 문서를 옮겨적다 틀리면 여기서 걸린다.

## 알아둘 것

- **토큰 3종은 «지름만 한 네모» 다.** 두근!·빌런(25×25) · 조우(35×35).
  펀치가 없어 가위로 자를 수 있게 네모로 뒀고, **지름을 그대로 한 변으로 썼다** —
  나중에 그 덱의 규격만 «토큰 · 원형 25/35» 로 바꾸면 크기 그대로 둥글어진다.
  레이어도 미리 둥글게(radius) 잡아둬서 다시 손볼 게 없다.
- **프린트묶기가 둘 있다.** 규격이 같은 덱을 한 종이에 이어 깔아 종이를 아낀다.
  묶인 덱 아무거나 «인쇄 / PDF» 를 누르면 묶음 전체가 나온다.

  | 묶음 | 덱 | 따로 | 묶어 | 아낌 |
  | --- | ---: | ---: | ---: | ---: |
  | 카드 묶음 (63×88) | 12 | 87쪽 | **76쪽** | 11장 |
  | 토큰 묶음 (25×25) | 2 | 2쪽 | **1쪽** | 1장 |

  조우 토큰(35×35)만 규격이 달라 혼자 남는다.

  > ⚠️ 묶으면 한 장에 여러 덱이 섞여 나온다. **자른 뒤 분류하는 수고**가 생기므로,
  > 시제품을 자주 뽑는 동안에는 이득이고 최종본은 덱별로 뽑는 편이 편하다.
- **재앙 뒷면 = 운명 뒷면.** 섞였을 때 구분되면 게임이 성립하지 않는다 (tokens.md §4).
  두 덱이 뒷면 틀을 각각 갖되 내용이 같게 맞춰뒀고, 검사가 이를 지킨다.
- **그림은 아직 없다.** 각 카드에 «그림» 자리(이미지 레이어)만 열려 있다.
  카드를 고르고 그 자리에 그림을 끌어다 놓으면 그 카드에만 들어간다.
- **정본은 `sub3/docs/rules/tokens.md` 다.** 예전 `sub3/nandeck/data/*.tsv` 에도 카드 자료가
  있었지만 문서와 어긋나 쓰지 않았고, 그 폴더는 2026-08-03 에 지웠다.

## 문서에서 발견한 어긋남

옮기면서 눈에 띈 것. 규칙 문서 쪽을 손봐야 한다.

- `scenario.md` 후반부 — 요약줄은 «③ 악령 관련 3장» 인데, 아래 소제목은
  «사자들의 합창 2장 + 종말의 전조 2장 = 4장» 이다. 예제는 **요약줄(3장)** 을 따랐다.
  그래야 후반부가 16장이 된다.
- 남주 성향 카드 20장의 **문구가 아직 없다.** 자리만 만들어뒀다.
